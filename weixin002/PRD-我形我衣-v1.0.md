## 1. 产品概述

### 1.1 产品定位

「我形我衣」是一款生活服务类微信小程序，核心能力是"专属数字人 + 照片级试穿"：

1. 用户输入身高、体重、三围、腿长、颈长等身材参数，并可选上传人脸照片与全身照，创建一个与自身身材高度一致的 3D 数字人；
2. 用户上传衣物图片或选择内置衣物模板，系统通过 AI 生成"自己穿着该衣物"的照片级效果图；
3. 数字人支持 3D 旋转查看，直观预览自己的身材比例。

### 1.2 解决的问题

- 网购衣物无法看到真实上身效果，买错尺码、款式压箱底；
- 想按自己的真实身材（而非模特身材）预览穿着效果；
- 衣柜衣物多但缺乏搭配思路（搭配建议在 V2 提供）。

### 1.3 产品目标（V1）

- 北极星指标：**人均每周有效试穿次数**（成功生成并保存 ≥1 张试穿效果图）；
- 关键结果：数字人创建完成率 ≥60%；首次试穿转化率 ≥40%；试穿出图成功率 ≥85%；出图耗时 P50 ≤15 秒。

> 注：V1 前期为**自用 / 小范围体验阶段**，以上指标用于自我校验产品质量，暂不作为商业化考核标准。

### 1.4 目标用户

- 核心人群：18–35 岁，习惯网购服饰、在意穿搭效果的男女用户；
- 次要人群：服装店主、穿搭达人（用效果图做展示或选品）。

### 1.5 设计原则

1. **隐私优先**：照片与身体数据最小化收集、加密存储、可一键删除；
2. **真实优先**：试穿结果追求照片级真实感，与"AI 生成效果"的说明并存；
3. **简单优先**：首次创建数字人 5 分钟内可完成，支持分步保存；
4. **合规先行**：AI 生成标识、深度合成备案、内容安全审核贯穿全流程。

## 3. 功能需求

### 3.1 用户账号与首次引导

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-01 | 微信授权登录 | 使用微信手机号快捷登录，获取 openid 作为用户标识 |
| FR-02 | 首次创建引导 | 首次进入展示创建数字人引导流程，分步填写、每步可保存 |
| FR-03 | 隐私授权 | 弹窗明示人脸照片与身体数据的用途、存储方式、删除方式；未授权前不采集任何照片 |

### 3.2 数字人创建与编辑

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-04 | 身材参数录入 | 必填：身高、体重、性别；选填：腰围、胸围、臀围、腿长、颈长、肩宽、臂长、鞋码、肤色 |
| FR-05 | 缺省估算 | 仅填身高体重时，按性别给出默认体型特征（肩宽、胸围、腰臀比等，参考标准人体比例数据），用户可逐项修改 |
| FR-06 | 人脸照片上传（选填） | 正面照 1 张（jpg/png，≤10MB）；上传则用于头部重建以提升"像你"程度，不要求 100% 相似；不上传时使用性别化默认头部形象 |
| FR-06a | 性别特征呈现 | 无论是否上传人脸照片，数字人均按所选性别呈现体型特征（肩宽、胸围、腰臀比、轮廓与默认发型），保证男女形象可区分 |
| FR-07 | 全身照上传（选填） | 用于肤色、体态校准；可跳过 |
| FR-08 | 生成数字人 | 服务端根据身材参数生成 3D 模型并渲染，生成中显示进度 |
| FR-09 | 3D 查看 | 单指旋转、双指缩放；支持"身材标注模式"（显示三围、腿长等标注线） |
| FR-10 | 数字人编辑 | 身材参数可修改并重新生成；保留最近 3 个历史版本 |
| FR-11 | 数字人删除 | 一键删除数字人及关联的照片与生成数据（异步清理，7 天内完成） |

### 3.3 衣物试穿（核心功能）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-12 | 试穿入口 | 数字人页"去试穿"按钮、首页快捷入口、模板衣物库 |
| FR-13 | 模板衣物库 | 首版内置 8-10 个基础模板（T 恤、衬衫、卫衣、牛仔裤、休闲裤、半身裙、连衣裙、外套等），后续版本扩充；按数字人体型自动匹配参考尺码 |
| FR-14 | 上传衣物图片 | 支持相册/拍照，jpg/png ≤20MB；自动识别品类（上装/下装/连衣裙/外套），失败可手动选择 |
| FR-15 | 图片预处理 | 自动抠图（背景移除）、方向矫正、透视归一化；处理结果可预览确认；非衣物、多人、涉敏图片给出明确提示并拦截 |
| FR-16 | AI 试穿生成 | 提交后进入异步生成队列，展示"生成中"状态与预计时长；完成后通过微信订阅消息通知 |
| FR-16a | 试穿底图一致性 | 生成时以 3D 数字人渲染图（正面/侧面）作为人体底图，人脸照片（如已上传）用于面部相似度，确保效果图的身材比例来自用户档案而非原始照片 |
| FR-17 | 多角度出图 | 默认生成正面效果图；可选生成侧面/背面（消耗更多额度） |
| FR-18 | 结果管理 | 试穿记录按时间倒序；单图预览、放大、保存到相册、分享 |
| FR-19 | 分享规范 | 分享卡片必须标注"AI 生成效果，仅供参考" |
| FR-20 | 对比视图 | 同一数字人不同衣物并排对比；他人数字人不可见、不可共享 |
| FR-21 | 失败处理 | 生成失败自动重试 1 次；仍失败则退回本次额度并提示原因（如图片质量不足） |

- **动作演示**：3D 骨骼动画（走/跑/跳）或 AI 视频生成，复用同一数字人档案；

## 5. 业务流程

### 5.1 首次创建数字人

登录 → 隐私授权 → 基本信息（性别/身高/体重）→ 身材参数（选填补充）→ 人脸照片上传 → 全身照（选填）→ 服务端生成 3D 模型 → 3D 预览确认 → 创建完成。

异常分支：
- 照片不合格 → 提示重拍（正脸、光线均匀）；
- 参数缺失 → 使用估算值，标注"估算"，允许后续修改；
- 中途退出 → 已填步骤自动保存，下次继续。

### 5.2 上传衣物试穿

选择/上传衣物图 → 品类识别 → 抠图与归一化 → 预览确认 → 提交生成任务 → 排队生成（可离开）→ 订阅消息通知 → 查看/保存/分享。

异常分支：
- 生成失败 → 自动重试 1 次 → 退回额度并提示原因；
- 内容违规 → 拦截并提示，不进入生成流程。

## 6. 合规要求

| 编号 | 要求 | 说明 |

| C-01 | 深度合成合规 | 涉及人脸/人体形象生成，按《互联网信息服务深度合成管理规定》完成算法备案；若使用第三方 API，须确认其已完成备案且授权范围覆盖本产品 |

## 9. 技术架构（概述）

### 9.1 客户端

- 微信小程序（原生或 Taro）；
- 数字人生成：采用**第三方数字人 SDK**（人脸重建 + 体型生成），前期快速验证效果；通过统一生成接口与自研方案解耦，后期可平滑替换；
- 3D 查看器：基于 WebGL（three.js 小程序适配方案），渲染 SDK 生成的数字人，支持旋转、缩放、标注。

### 9.2 服务端

- API 网关 + 用户/档案服务 + 任务队列（异步生成）+ 对象存储（腾讯云 COS 等）+ 数据库（MySQL/PostgreSQL + Redis）；
- 生成任务采用异步队列：提交 → 排队 → 调用 AI 服务 → 回调写库 → 推送订阅消息。

### 9.3 AI 服务（统一接口层，可替换供应商）

| 能力 | 候选方案 | 选型标准 |
| --- | --- | --- |
| 抠图 | rembg / 国内云厂商 API | 处理耗时、单价 |
| 品类识别 | 图像分类 API | 准确率 |
| 试穿生成 | 第三方虚拟试穿 API 或自建模型（如 Outfit Anyone 类）；**以 3D 数字人渲染图作为人体底图**，保证身材比例来自用户档案 | 备案资质、出图质量、单价、SLA |
| 内容审核 | 微信内容安全 / 云厂商审核 | 覆盖范围、响应速度 |

## 12. 风险与应对

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 试穿生成效果一致性/质量不稳定 | 高 | 多供应商备选、效果对比测试、结果页注明"AI 生成效果仅供参考" |
| AI 生成成本失控 | 高 | 每日免费额度限制、结果缓存复用、任务合并、后续会员付费 |
| 深度合成算法备案周期长 | 高 | 与开发并行启动；或先接入已备案的第三方 API |
| 微信审核驳回（类目/内容） | 中 | 类目选「工具-图片处理」并保持功能一致，提前提交咨询 |
| 人脸数据隐私风险 | 中 | 最小化收集、单独授权、加密存储、可删除、数据不出境 |
| 3D 人脸"不像用户" | 中 | 人脸照片为选填，未上传时使用性别化默认形象；上传时迭代人脸方案并明示"相似度受照片质量影响" |
