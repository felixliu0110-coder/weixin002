## 1. 产品概述

### 1.1 产品定位

「我形我衣」是一款生活服务类微信小程序，核心能力是"AI 专属数字人 + 照片级试穿视频"：

1. 用户输入身高、体重、三围、腿长、颈长等身材参数，并可选上传人脸照片与全身照，创建一套与自身身材高度一致的 AI 写实人物三视图（正面/侧面/背面）；
2. 用户上传衣物图片或选择内置模板衣物，AI 以原图为参考生成服装四视图，再结合人物三视图生成"自己穿着该衣物"的照片级效果；
3. 试穿结果以 180° 原地转身视频呈现，可收藏、保存模板与分享。

### 1.2 解决的问题

- 网购衣物无法看到真实上身效果，买错尺码、款式压箱底；
- 想按自己的真实身材（而非模特身材）预览穿着效果；
- 衣柜衣物多但缺乏搭配思路（搭配建议在 V2 提供）。

### 1.3 产品目标（V1）

- 北极星指标：**人均每周有效试穿次数**（成功生成并保存 ≥1 次试穿视频）；
- 关键结果：数字人创建完成率 ≥60%；首次试穿转化率 ≥40%；试穿生成成功率 ≥85%；生成耗时以供应商实际能力为准（前端全程展示进度）。

> 注：V1 前期为**自用 / 小范围体验阶段**，以上指标用于自我校验产品质量，暂不作为商业化考核标准。

### 1.4 目标用户

- 核心人群：18–35 岁，习惯网购服饰、在意穿搭效果的男女用户；
- 次要人群：服装店主、穿搭达人（用生成结果做展示或选品）。

### 1.5 设计原则

1. **隐私优先**：照片与身体数据最小化收集、加密存储、可一键删除；
2. **真实优先**：试穿结果追求照片级真实感，与"AI 生成效果"的说明并存；
3. **简单优先**：首次创建数字人 5 分钟内可完成，支持分步保存；
4. **合规先行**：AI 生成标识、深度合成备案、内容安全审核贯穿全流程。

## 3. 功能需求

### 3.1 用户账号与首次引导

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-01 | 微信授权登录 | 使用微信手机号快捷登录，获取 openid 作为用户标识 |
| FR-02 | 首次创建引导 | 首次进入展示创建数字人引导流程，分步填写、每步可保存 |
| FR-03 | 隐私授权 | 弹窗明示人脸照片与身体数据的用途、存储方式、删除方式；未授权前不采集任何照片 |

### 3.2 数字人创建与编辑

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-04 | 身材参数录入 | 必填：身高、体重、性别；选填：腰围、胸围、臀围、腿长、颈长、肩宽、臂长、鞋码、肤色 |
| FR-05 | 缺省估算 | 仅填身高体重时，按性别给出默认体型特征（肩宽、胸围、腰臀比等，参考标准人体比例数据），用户可逐项修改 |
| FR-06 | 人脸照片上传（选填） | 正面照 1 张（jpg/png，≤10MB）；上传则用于提升人物三视图的"像你"程度，不要求 100% 相似；不上传时使用性别化默认形象 |
| FR-06a | 性别特征呈现 | 无论是否上传人脸照片，数字人均按所选性别呈现体型特征（肩宽、胸围、腰臀比、轮廓与默认发型），保证男女形象可区分 |
| FR-07 | 全身照上传（选填） | 用于肤色、体态校准；可跳过 |
| FR-08 | 生成数字人 | 创建向导完成时，服务端根据身材参数与照片（如有）调用 AI 生成写实人物三视图（正面/侧面/背面），生成一次并复用；生成中显示进度，进度到 100% 才算完成 |
| FR-09 | 数字人查看 | 数字人页展示人物三视图（正面/侧面/背面），直观预览自己的身材比例；不做 3D 渲染 |
| FR-10 | 数字人编辑 | 身材参数可修改并重新生成三视图；保留最近 3 个历史版本 |
| FR-11 | 数字人删除 | 一键删除数字人及关联的照片与生成数据（异步清理，7 天内完成） |

### 3.3 衣物试穿（核心功能）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-12 | 试穿入口 | 数字人页"去试穿"按钮、首页快捷入口、试衣页五分类衣物库 |
| FR-13 | 模板衣物库 | 试衣页按五个分类组织：上衣 / 裤子 / 头饰 / 鞋子 / 其他；内置模板衣物展示在各分类下，后续版本扩充；分类卡片显示该分类衣物件数 |
| FR-14 | 上传衣物图片 | 支持相册/拍照，jpg/png ≤20MB；用户手动填写衣物名称并选择分类（上衣/裤子/头饰/鞋子/其他），**不做自动品类识别**；上传原图保存至云存储，试衣页保存的一律为用户原图 |
| FR-15 | 原图直用（不做抠图） | 上传仅做格式/大小校验与内容安全检测；**不做抠图、背景移除、透视归一化或透明化处理**，原图直接作为 AI 生成参考图；非衣物、多人、涉敏图片给出明确提示并拦截 |
| FR-16 | 服装四视图生成与缓存 | 首次试穿某衣物时，AI 以原图为参考生成服装四视图（正面/45° 斜侧/局部细节/背面，2×2 同画布）并缓存复用；单张原图 ↔ 四视图 1:1 对应，删除原图时对应四视图一并删除 |
| FR-17 | AI 试穿视频生成 | 提交后进入异步生成队列，展示"生成中"状态与预计时长；以人物三视图为人体基准、服装四视图为衣物参考，调用 AI 生成 180° 原地转身试穿视频（正面→侧面→背面）；完成后通过微信订阅消息通知；同衣物组合 7 天内缓存复用（秒回），生成失败自动重试 1 次 |
| FR-17a | 试穿一致性 | 生成时以 AI 人物三视图作为人体底图，人脸照片（如已上传）用于面部相似度，确保视频中身材比例来自用户档案；衣物版型、颜色、细节与参考图一致 |
| FR-18 | 结果管理 | 试穿记录按时间倒序；试穿结果以视频形式预览，支持收藏、保存到相册、分享 |
| FR-19 | 分享规范 | 分享卡片必须标注"AI 生成效果，仅供参考"；结果带「AI 生成」标识 |
| FR-20 | 收藏 | 试穿结果可收藏（独立收藏页）；收藏后可选择是否同时保存到相册 |
| FR-20a | 对比视图 | 同一数字人不同衣物并排对比；他人数字人不可见、不可共享 |
| FR-21 | 失败处理 | 生成失败自动重试 1 次；仍失败则提示原因（如图片质量不足），不重复计费/不重复消耗 |

## 5. 业务流程

### 5.1 首次创建数字人

登录 → 隐私授权 → 基本信息（性别/身高/体重）→ 身材参数（选填补充，缺省估算可改）→ 人脸照片上传（选填）→ 全身照（选填）→ AI 生成人物三视图 → 预览确认 → 创建完成。

异常分支：
- 照片不合格 → 提示重拍（正脸、光线均匀）；
- 参数缺失 → 使用估算值，标注"估算"，允许后续修改；
- 中途退出 → 已填步骤自动保存，下次继续。

### 5.2 上传衣物试穿

选择/上传衣物图 → 填写名称与分类（上衣/裤子/头饰/鞋子/其他）→ 内容安全检测 → 预览确认 → AI 生成服装四视图（首次，之后缓存复用）→ 结合人物三视图生成 180° 转身试穿视频 → 订阅消息通知 → 查看/收藏/保存/分享。

异常分支：
- 生成失败 → 自动重试 1 次 → 仍失败则提示原因（不重复消耗）；
- 内容违规 → 拦截并提示，不进入生成流程。

## 9. 技术架构（概述）

### 9.1 客户端

- 原生微信小程序（pages 原生页面 + 自定义组件 + 自定义 TabBar）；
- AI 能力全部走云函数统一接口，前端不直接接触供应商 API Key。

### 9.2 服务端

- 微信云开发：云函数（AI 生成编排、内容安全检测、微信登录、存储管理）+ 云数据库 + 云存储；
- 生成任务采用异步流程：提交 → 排队 → 调用 AI 服务 → 写库 → 推送订阅消息；
- AI 生成图片自动保存至云存储（cloud:// 文件 ID）；试穿视频暂存供应商链接（downloadFile 域名已配置）。

### 9.3 AI 服务（统一接口层，可替换供应商）

| 能力 | 说明 | 选型标准 |
| --- | --- | --- |
| 人物三视图 | 创建向导完成时生成写实三视图（正面/侧面/背面），一次生成后复用 | 人像真实感、备案资质、单价 |
| 服装四视图 | 以用户原图为参考生成 2×2 四视图（正面/45° 斜侧/局部细节/背面），首次生成并缓存 | 版型/颜色/细节一致性 |
| 试穿视频 | 人物三视图 + 服装四视图 + 视频提示词 → 180° 原地转身视频 | 生成速度、动作自然度、一致性、SLA |
| 内容审核 | 微信内容安全 API（imgSecCheck），上传衣物时检测 | 覆盖范围、响应速度 |

> 当前接入 Agnes AI（生图 + 生视频），通过可插拔 AIGC 适配器支持后续更换模型/供应商。

## 10. 埋点与数据指标

### 10.1 关键事件

- 创建漏斗：数字人创建开始 → 基本信息完成 → 照片上传完成 → 三视图生成成功；
- 试穿漏斗：进入试穿 → 上传/选模板 → 名称分类确认 → 四视图生成 → 视频生成成功 → 收藏/保存/分享；
- 质量与体验：生成耗时、失败原因分布、四视图缓存命中率、模板 vs 上传占比。

### 10.2 指标目标

## 12. 风险与应对

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 试穿生成效果一致性/质量不稳定 | 高 | 多供应商备选、效果对比测试、结果页注明"AI 生成效果仅供参考" |

| 深度合成算法备案周期长 | 高 | 与开发并行启动；或先接入已备案的第三方 API |
| 微信审核驳回（类目/内容） | 中 | 类目选「工具-图片处理」并保持功能一致，提前提交咨询 |
| 人脸数据隐私风险 | 中 | 最小化收集、单独授权、加密存储、可删除、数据不出境 |
| 数字人三视图与本人相似度不足 | 中 | 人脸照片为选填，未上传时使用性别化默认形象；明示"相似度受照片质量影响"，支持重新生成 |
