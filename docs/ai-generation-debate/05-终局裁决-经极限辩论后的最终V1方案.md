# 终局裁决：经过极限辩论后的最终方案

> 每个争议点都经历了「我的原方案 → ChatGPT 反驳 → 我反驳 ChatGPT → 我反驳自己 → 最终裁决」的完整链路。
> 没有和气，只有逻辑。

---

## 争议 1 终局：三视图到底怎么生成

### 辩论全记录

| 回合 | 立场 | 论点 |
|------|------|------|
| 我的原方案 | 3 次独立生成 + 级联 | 每张 1024×1024，人脸清晰 |
| ChatGPT 反驳 | V1 保持合成图 | 成本 ×3、时间 ×3、身份漂移 |
| 我反驳 | 18% 成本增量换来锚定质量 ×3 | 三视图只生成一次，分摊到多次试穿成本可忽略 |
| 我反驳自己 | 级联参考的漂移真的比合成图好吗？ | 合成图隐式漂移 vs 级联显式漂移，到底哪个更严重？ |

### 极限追问

**级联参考到底靠不靠谱？** 当我用正面图作参考生成侧面图时，通用文生图模型（Agnes / OpenAI）对"参考图中的同一个人"的遵循度大概 60-70%。这意味着 30-40% 的概率侧面图的人脸和正面图不一样。

**合成图的隐式漂移呢？** 合成图里三个视图的人脸是同一次生成、同一个 context，自然倾向于同一个人。虽然每个视图只有 340px，但三个视图之间的一致性比级联生成好。

**340px 的人脸够不够用？** ArcFace 等人脸编码模型设计工作在 112×112，340px 绰绰有余。但问题不是编码够不够——是生成质量。340px 宽的脸上，眼睛的形状、鼻子的轮廓、嘴唇的厚度都是模糊的。这张脸作为后续试穿的参考，试穿结果的脸也会模糊/通用化。

**有没有第三条路？** 有。

### 最终裁决

**V1：1 张高分辨率正面图 + 1 张合成三视图（作为预览），共 2 次调用。**

```
Step 1: 生成 1024×1024 高分辨率正面全身图（身份锚定图）
        → 这是核心资产，后续所有试穿都用它作参考
        → 成本：1 次调用

Step 2: 生成合成三视图（正面/侧面/背面并排，1024×1024）
        → 这是用户预览用的，让用户看到"三个角度长什么样"
        → 试穿时不用这张图做参考（用 Step 1 的高清正面图）
        → 成本：1 次调用

总计：2 次调用（而非 3 次），同时获得高质量锚定图 + 三视图预览
```

**为什么这是最优解**：

- 锚定图 1024×1024，人脸清晰，试穿参考质量有保障；
- 合成图的三视图虽然分辨率低，但作为预览足够——用户只需确认"大致是我"；
- 试穿时只用锚定图作参考，不用合成图——锚定图质量决定了试穿质量；
- 2 次调用而非 3 次，成本介于合成图和 3 次独立之间；
- V2 可以用锚定图级联生成高分辨率侧面/背面图，升级路径清晰。

**谁对了**：我（三视图质量很重要）和 ChatGPT（成本和漂移要考虑）都对了一半。最终方案是两者的精确缝合——核心锚定图用高质量独立生成，预览用合成图，各取所长。

## 争议 2 终局：服装四视图到底留不留

### 辩论全记录

| 回合 | 立场 | 论点 |
|------|------|------|
| 我的原方案 | 4 次独立生成 | 每张高分辨率，细节充分 |
| ChatGPT 反驳 | VTON 不需要四视图，取消 | 用原图就行 |
| 我反驳 | 视频需要背面信息 | 转过身之后模型从哪知道衣服背面长什么样？ |
| 我反驳自己 | V1 不做视频了，背面图给谁用？ | 如果 V1 不做视频，背面图确实没用 |

### 极限追问

**V1 不做视频，那背面图给谁用？** 没人用。V1 的 VTON 只需要一张服装原图。

**V1.5 做视频时需要背面图吗？** 需要，但到时候再生成就行，不需要现在就生成并缓存。

**VTON 模型能接受多张服装图吗？** 大多数不能。标准 VTON 输入是 1 张人物图 + 1 张服装图。即使生成了背面图，VTON 也用不上。

**那服装背面图在什么场景下有用？** 只在图生视频时有用——作为参考图告诉视频模型"转过身之后衣服长这样"。

### 最终裁决

**V1：不生成服装四视图，VTON 直接用原图。V1.5 做视频时按需生成 1 张服装背面图。**

```
V1 服装资产：
  用户上传原图 → 直接作为 VTON 输入
  不做任何额外生成
  不缓存四视图

V1.5 服装资产（做视频时）：
  原图（正面，已有）
  + 按需生成 1 张背面图（供视频参考）
  不需要侧面图和细节特写
```

**谁对了**：ChatGPT 对了——V1 确实不需要四视图。我之前反驳说"视频需要背面图"，但既然 V1 不做视频，这个反驳在 V1 阶段不成立。不过我的判断在 V1.5 会重新生效。

## 争议 3 终局：体型偏差检测做不做

### 辩论全记录

| 回合 | 立场 | 论点 |
|------|------|------|
| 我的原方案 | 硬阈值检测 | 偏差 >15% 重试 |
| ChatGPT 反驳 | 透视/焦距/遮挡导致不可靠 | 改为软监控 |
| 我反驳 | 粗粒度方向性检查可行 | 90kg 和 60kg 差异巨大，不可能被镜头焦距抹平 |
| 我反驳自己 | 检测做在哪个环节？ | VTON 保留了人物体型，真正出错的是三视图生成 |

### 极限追问

**体型偏差是从哪来的？** 如果用 VTON，VTON 保留人物图像中的体型。所以体型对不对，取决于输入给 VTON 的那张人物图——也就是锚定图的体型对不对。

**锚定图的体型由谁决定？** 由生成锚定图的文生图模型决定，受 prompt 中体型描述的影响。

**所以检测应该做在锚定图上，不是做在试穿结果上。** 这点我之前没想清楚。

**锚定图上的粗粒度检测可靠吗？** 锚定图是纯白背景、正面站姿、固定构图——没有透视变化、没有姿态变化、没有复杂场景干扰。在这个受控条件下，用关键点比例做方向性检查是可行的。

具体来说：
- 肩宽/身高比：在正面白底图中，这个比例相对稳定，不受镜头焦距影响（焦距影响绝对尺寸，不影响比例）
- 腰宽/肩宽比：同样在正面白底图中相对稳定
- BMI 类别（过轻/正常/偏重/肥胖）：从肩腰比就能粗判

### 最终裁决

**V1：在锚定图上做粗粒度体型方向性检测。不做试穿结果上的体型检测。**

```
锚定图体型检测（V1）：

1. 用 MediaPipe 提取关键点
2. 计算比例：
   - 肩宽指数 = 肩宽像素 / 身高像素
   - 腰宽指数 = 腰宽像素 / 身高像素
3. 从用户参数推算 BMI 类别：
   - BMI < 18.5 → 偏瘦
   - BMI 18.5-24 → 正常
   - BMI 24-28 → 偏重
   - BMI > 28 → 肥胖
4. 交叉验证：
   - 用户 BMI 偏瘦 + 锚定图腰宽指数大 → ⚠️ 标记偏差
   - 用户 BMI 肥胖 + 锚定图腰宽指数小 → 🔴 拦截重试
   - 其他情况 → ✅ 通过
5. 只做方向性判断，不做精确比对
6. 只在锚定图（白底正面站姿）上做，不在试穿结果上做
```

**谁对了**：我（粗粒度检测可行）比 ChatGPT（不做检测）更对，但我需要修正检测环节——做在锚定图上而非试穿结果上。ChatGPT 对的一点是：透视和姿态确实会干扰检测——但锚定图恰好是受控条件（白底正面站姿），避开了这些干扰。

## 争议 4 终局：白底 vs 非白底

### 辩论全记录

| 回合 | 立场 | 论点 |
|------|------|------|
| ChatGPT | V1 白底 | 减少伪影，VTON 训练分布以白底为主 |
| 我反驳 | 白底让用户觉得"AI 生成的" | 加简约室内场景增加真实感 |
| 我反驳自己 | 场景增加了伪影风险 | 如果场景版本生成质量差，反而更降低信任 |

### 极限追问

**白底 = "AI 生成的"这个判断有数据支撑吗？** 没有。这是我的直觉判断。有可能用户根本不在意背景，只在意"这个人像不像我"和"衣服对不对"。

**VTON 在非白底上效果真的会差吗？** 取决于具体模型。很多 VTON 模型是在多样化背景上训练的。但确实，白底是最稳定的分布。

**加一个场景选项的工程成本有多高？** 极低——只是 prompt 里把"纯白背景"换成"简约室内"的事。但如果场景版本质量不稳定，用户试一次差的效果就会流失。

### 最终裁决

**V1 默认白底。但在设置中提供一个"真实场景"实验开关，用于 A/B 测试收集数据，不做正式功能。**

```
V1 背景策略：
  默认：纯白背景（所有用户）
  隐藏选项：「设置 → 实验功能 → 真实场景模式」
    → 开启后 prompt 替换为简约室内场景
    → 生成失败或质量差时自动降级回白底
    → 后台记录两个模式的成功率、用户满意度
  V1.5 决策：根据数据决定是否正式上线场景选项
```

**谁对了**：ChatGPT 对了——V1 默认白底是最稳的。我"白底降低信任"的判断可能是对的，但没有数据就推正式功能太冒险。折中方案：白底默认 + 场景作为 A/B 测试实验功能，用数据说话而非直觉。

## 争议 5 终局：V1 做不做视频

### 辩论全记录

| 回合 | 立场 | 论点 |
|------|------|------|
| 我的原方案 | 微动态视频 3s | 成功率高，比静态图"活" |
| ChatGPT | 图生视频 A 方案 | 试穿图→视频 |
| 我反驳 | 3s 微动态和静态图区别不大 | 手机上几乎看不出呼吸/微摆 |
| 我反驳自己 | 完全不做视频，产品会不会太平淡？ | 用户选完衣服只看到一张静态图，体验完整吗？ |

### 极限追问

**3 秒微动态真的看不出来吗？** 在大屏幕上能看出区别（布料轻微晃动、头发微动），但在手机竖屏看一张全身图——确实很难感知。除非做半身特写+放大，但那就不是"全身试穿效果"了。

**不做视频，产品会不会太平淡？** 这是一个产品问题不是技术问题。如果 V1 的核心体验是"看到自己穿上这件衣服的真实效果"，那一张高质量试穿图就够了。视频是锦上添花。

**多角度静态切换比微动态视频更好吗？** 更好。理由：
1. 用户可以主动滑动查看侧面/背面，有交互感；
2. 每个角度都是 VTON 生成的高质量图，不像视频可能有伪影；
3. 零视频 API 成本；
4. 可以无限次查看不损失画质。

**但 3 个角度 = 3 次 VTON 调用 = 3 × 成本。值吗？** 对于"1 件衣服试穿"的场景，3 次调用确实贵。而且 V1 如果只支持 1 件衣服，用户的核心需求就是"这件衣服穿在我身上正面看怎么样"——侧面和背面是加分项，不是必需。

### 最终裁决

**V1：1 张正面试穿图（1 次 VTON 调用）。不做视频，不做多角度。**

```
V1 试穿结果：
  1 张正面全身试穿图（VTON 生成）
  可保存、可分享、可收藏
  这就是完整结果

V1.5 增值：
  + 侧面/背面试穿图（额外 2 次 VTON，可选生成）
  + 前端三角度切换 + 过渡动画

V2 增值：
  + 微动态视频（图生视频，基于正面试穿图）
  + 小角度转身视频（90°，基于正面试穿图）
```

**谁对了**：谁都不完全对。ChatGPT 的"A 方案图生视频"在 V1 太冒险（视频质量没保证），我原方案的"微动态"太鸡肋（和静态图差异不大），我后来的"3 角度静态"在 V1 太贵（3 次 VTON）。最终的 V1 只做 1 张正面试穿图，是成本和效果的精确平衡点。

## 争议 6 终局：多件衣物到底支持几件

### 辩论全记录

| 回合 | 立场 | 论点 |
|------|------|------|
| ChatGPT | V1 最多 3 件 | 上装+下装+鞋 |
| 我反驳 | VTON 一次只能换 1 件，3 件要级联误差累积 | V1 限 1 件 |
| 我反驳自己 | 上装+下装是不同区域，可以分开 VTON 不叠加误差 | 2 件可能可行 |

### 极限追问

**VTON 对上装和下装的处理真的独立吗？** 是的。大多数 VTON 模型有 upper-body 和 lower-body 两种模式。上装只替换上半身区域，下装只替换下半身区域。两个区域不重叠，所以可以分别调用、不叠加误差。

流程：
```
1. 人物正面图 + 上装图 → VTON (upper) → 穿上装的人物图
2. 穿上装的人物图 + 下装图 → VTON (lower) → 完整穿搭图
```

第 2 步时，模型只修改下半身区域，上半身保持第 1 步的结果不变。这不是误差累积，而是分区替换。

**鞋子怎么办？** 鞋子的 VTON 是个独立问题——有些模型支持 footwear try-on，有些不支持。V1 先不管鞋子，用户看到的是"穿这件衣服的效果"，鞋用原图里人物自带的鞋。

**2 件上装（内搭+外套）呢？** 这才是真正的问题。标准 VTON 的 upper-body 模式会替换整个上半身区域，无法做到"在T恤外面加一件外套"。需要专门的 multi-layer VTON 或 inpainting，V1 不该碰。

### 最终裁决

**V1：最多 2 件——1 件上装 + 1 件下装，分 2 次 VTON 调用（分区替换，无误差累积）。**

```
V1 衣物组合：
  模式 A：仅上装（1 次 VTON）
  模式 B：仅下装（1 次 VTON）
  模式 C：上装 + 下装（2 次 VTON，分区替换）

  不支持：2 件上装叠穿、2 件下装、鞋子、配饰
  前端限制：选择页面最多勾选 2 件，且必须 1 上 + 1 下

V1.5：
  + 鞋类试穿（如模型支持）
  + 内搭+外套叠穿（inpainting 策略）

V2：
  + 配饰（帽子、围巾）
  + 多层叠穿
```

**谁对了**：我（V1 限 1 件）过于保守——上装+下装的分区替换确实可行。ChatGPT（V1 最多 3 件）过于激进——上装+下装+鞋子里，鞋子在 V1 阶段不可控。2 件（1 上 + 1 下）是精确的平衡点。

## 终极裁决汇总

| 争议点 | 我的原方案 | ChatGPT 建议 | 最终裁决 |
|--------|-----------|-------------|---------|
| 三视图 | 3 次独立 | V1 保持合成 | **1 高清正面图 + 1 合成三视图，2 次调用** |
| 四视图 | 4 次独立 | 取消 | **V1 取消，V1.5 按需生成背面图** |
| 体型检测 | 硬阈值 | V1 不做 | **V1 在锚定图上做粗粒度方向性检查** |
| 背景 | 白底+场景选项 | V1 纯白底 | **默认白底 + 隐藏场景实验开关做 A/B 测试** |
| 视频 | 微动态 3s | 图生视频 | **V1 不做视频，只做 1 张正面试穿图** |
| 多件衣物 | V1 限 1 件 | V1 最多 3 件 | **V1 最多 2 件（1 上 + 1 下），分区 VTON** |
